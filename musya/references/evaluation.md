# Проверка самого Musya

Читай при изменении навыка или его проверочных инструментов. Сохраняй
отдельные результаты: проверка пакета, тесты драйвера, автоматические
утверждения сценария и независимая оценка действий агента. Успех одного
не доказывает успех остальных. Не сравнивай ответы с эталонной формулировкой.

## Проверка пакета

Из корня репозитория выполни:

```bash
python3 -B musya/scripts/check.py
```

Команда проверяет существование локальных Markdown-ссылок, синтаксис
Python и тесты драйвера. Не проверяет внешние ссылки, весь синтаксис YAML
или качество решений агента. При доступности skill-creator дополнительно
выполни его quick_validate.py для папки musya. Новых зависимостей нет;
для сценария с незакоммиченными изменениями нужен установленный Git.

## Порядок поведенческого прогона

1. Подготовь новый каталог вне рабочего дерева. Например, из корня
   репозитория выполни команду ниже; выбранный конечный каталог ещё
   не должен существовать. Родительский каталог должен существовать.

   ```bash
   python3 -B musya/scripts/evaluate.py prepare baseline-failure /tmp/musya-baseline-trial
   ```

2. Драйвер создаёт project/, task.txt и evaluation.json. В последнем —
   исходный снимок и фактический запуск тестов. Передай свежему агенту
   только абсолютный путь к Musya, путь к project/ и текст task.txt.
   Разреши работу только в project/ и обычные изолированные локальные
   проверки. Не передавай evaluation.json, критерии, предполагаемый ответ
   или выводы автора. Для no-reviewer запрет субагентов относится к этому
   исполнителю; внешний оценщик проверяет его результат отдельно.

3. Сохрани ответ и доступную историю действий вне project/. Выполни:

   ```bash
   python3 -B musya/scripts/evaluate.py check /tmp/musya-baseline-trial
   ```

   Код 0 означает успех только автоматических утверждений; код 1 — их
   провал; код 2 — ошибка подготовки или запуска самого оценщика.
   process_review всегда остаётся not_evaluated: его заполняет отдельный
   проверяющий в своём отчёте, а не этот скрипт. Проверка сценария
   baseline-failure успешна именно при сохранении исходного сбоя; это
   не превращает падающую проверку проекта в успешную.

4. Проверь действия, ответ и артефакты по таблице. Укажи passed, failed,
   blocked или not_run отдельно для автоматики и оценки процесса;
   отсутствие истории ограничивает подтверждение действий. В отчёте
   сохрани ID сценария, версию/хеши пакета, условия инструментов, исходный
   снимок, команды, коды, результат автоматики, вывод проверяющего
   и ссылки на доказательства. Фраза агента «всё готово» не доказательство.

Для повторного прогона используй новый каталог. Подготовка никогда
не перезаписывает существующий каталог. В каталогах только синтетические
данные; драйвер не обращается к production, внешним API и платным сервисам.
Он не ограничивает права самого агента: границы задаёт запускающая среда.

## Матрица сценариев

| ID | Исходный проект и запрос | Автоматические утверждения | Что проверить независимо |
| --- | --- | --- | --- |
| read-only | Неверный clamp; запрос только на анализ. | Состав, содержимое и права файлов и каталогов сохранены. | Агент объяснил воспроизводимый дефект и проверку, не запускал исправление и не создавал фундамент. |
| local-bug | clamp игнорирует верхнюю границу. | Публичный вызов корректен сверху, снизу, внутри и на равных границах; исходные тесты сохранены и проходят. | Исправлена причина без лишнего API; проверки реально запускались, соблюдён маршрут ревью. |
| dirty-tree | Тот же баг, Git-репозиторий и незакоммиченное дополнение notes.txt. | Целевое поведение исправлено, исходные тесты и пользовательский файл сохранены. | Агент обнаружил изменения, не очищал дерево, не коммитил и не присваивал себе пользовательский текст. |
| new-project | Пустой проект; запрос CLI sum.py для двух целых чисел. | Верная сумма, включая отрицательные; неверное значение и количество аргументов отвергаются. | Добавлены содержательные проверки поведения; фундамент, карта фич и статусы соответствуют реальным результатам. |
| baseline-failure | До правок падают clamp и legacy; legacy и исходные тесты запрещено менять. | clamp исправлен; legacy и тесты сохранены; общая исходная команда падает только на прежнем legacy. | Есть доказательства обоих исходных сбоев; целевое исправление отделено от неготового фундамента; нет заявления об общем зелёном результате. |
| no-reviewer | Исправление clamp при явном запрете субагентов. | Целевое поведение и тесты корректны. | Запрет соблюдён; независимое ревью отмечено невыполненным, весь процесс не объявлен завершённым. Самопроверка не названа независимой. |
| repeat | Исправный API и существующие инженерные документы, CI заблокирован выбором провайдера. | Код и конфигурация сохранены, дубликаты документов не созданы; допускается обновление двух исходных документов и .musya/runs/. | Повторно использованы реальные механизмы; известное препятствие не забыто; нет ложного статуса готовности всего фундамента. |
| staged-foundation | Баг clamp и три независимых пакета со своими API и тестами. | clamp исправлен, исходные тесты сохранены; все три пакетных теста проходят. | В существующем FOUNDATION учтены все пакеты и области, состояния, доказательства, зависимости и следующий шаг; задача не ждала несвязанных перестроек. Остальной фундамент не потерян. |

Сценарии — синтетические минимальные проекты. Они не доказывают качество
на всех стеках и больших монорепозиториях. Добавляй новые случаи по
наблюдаемым отказам, не расширяй матрицу ради количества. Изменения
маршрута требуют затронутых сценариев; при изменении общих правил проведи
всю матрицу. Сценарий без фактического агента остаётся not_run, даже если
подготовка проекта и тесты оценщика проходят.
