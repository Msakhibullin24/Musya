# Фундамент Musya

## Устройство и команды

musya/ — переносимый пакет навыка: основной маршрут в SKILL.md,
правила этапов в references/, политика вызова в agents/openai.yaml.
scripts/evaluate.py создаёт синтетические проекты и проверяет их
наблюдаемый результат; scripts/check.py проверяет ссылки, синтаксис
Python и запускает unittest из tests/. Зависимости — Python 3 и Git;
библиотеки Python только стандартные. Продуктового хранилища и миграций нет.

Из корня репозитория: `python3 -B musya/scripts/check.py`.
GitHub Actions использует ту же команду; внешний запуск CI подтверждается
отдельно после публикации. Локально приложение проверки запускается
сквозным вызовом evaluate.py prepare/check в изолированных каталогах.

## Контракты и границы

- Исторический skill.md и исходный нормативный блок сохраняются.
- Подготовка принимает новый каталог и не перезаписывает существующий.
  Данные оценки находятся вне project/, исполнитель работает в project/.
- check возвращает 0 для успешных автоматических утверждений, 1 для их
  провала, 2 для ошибки самого оценщика. process_review не оценивается
  автоматически. Исходный сбой приложения может быть ожидаемым результатом
  сценария; код его собственной проверки остаётся ненулевым.
- Скрипт не является средой ограничения прав агента. Все данные
  синтетические; вызовы приложений локальные. Публикация не требуется.
- Отчёты в .musya/runs/ не входят в Git и не содержат секретов.

| CI | заблокировано внешним запуском | GitHub выбран по origin; конфигурация вызывает локальную команду, публикация не выполнялась. | Проверить внешний запуск после разрешённой публикации. |

Исходных поведенческих прогонов навыка до изменения нет: сравнительное
улучшение качества не доказано. Проверка YAML доступным quick_validate.py
и успешные тесты драйвера не устраняют это ограничение. Матрица покрывает
минимальные Python-проекты; она не доказывает качество на всех стеках.
Оценка действий использует снимки, артефакты и ответы исполнителей;
полная машинная история каждого вызова инструмента не собиралась.
В изолированных проектах исполнители честно отметили недоступное ревью
и неизвестный CI как препятствия, а не объявили свой процесс завершённым.
Это ожидаемая проверка статуса и не препятствие созданию самой матрицы.
